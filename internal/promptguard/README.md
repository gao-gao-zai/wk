# 系统提示词替换与拦截诊断

入口：控制台侧栏 **系统提示词**，地址 `#/prompt-guard`。此功能用于通用的、管理员维护的字面内容替换。不会自动生成或猜测“同义”文本。

## 功能与交互

1. **替换规则**：新增、编辑、启停、删除及上下移动规则；每条包含名称、匹配原文和替换内容。支持任意多行字符串，区分大小写、精确匹配，替换为空表示删除。可选匹配末尾边界（英文句点、空格、制表符、换行或文本末尾）。列表顺序就是执行顺序，每条规则执行一次，后面的规则可匹配前面的结果。不使用正则，不反复递归执行规则。
2. **作用范围**：Chat Completions 的 `system`、`developer` 消息及其 `text` / `input_text` 内容块。Responses API 的 `instructions` 经现有转换后使用同一处理链。用户、助手、工具消息及非文本内容不改写。匹配不会跨消息或内容块拼接；界面保留这些边界。
3. **兼容顺序**：通用规则（含迁移规则）→ 原有协议归一化 → 原有指纹处理。升级首次启动时自动将 Codex 的 1 条、DSH 的 3 条替换规则导入列表，按有效旧配置（含环境变量）保留启停状态。旧开关关闭时也会导入对应的禁用规则；全新安装得到 4 条禁用预置规则。之后这些内容全部由新列表控制，保存立即生效。
4. **拦截记录**：当上游 HTTP 错误响应或 SSE 错误帧包含结构化 `code=11128` 时，保存原始与实际出站的完整系统消息，包括角色、顺序及内容块，不保存业务用户消息、工具调用历史、Authorization 或账号凭据。11140、11101 及文本中偶然出现的“11128”不会触发记录。同一模型、原始与出站提示词合并为一条，累计发生次数。
5. **登录提醒**：管理员登录后立即读取待处理计数，并每 30 秒更新。提醒跳转拦截列表。规则命中不等于问题解决；只有当前规则下的完整系统提示词验证通过，记录才解除提醒。规则、兼容设置变更，或该记录再次报错，都会要求重新验证。
6. **定位工作台**：详情抽屉展示两份完整提示词、触发片段、逐次探测结果及请求预算。可重新定位、预览替换、设置规则、验证和取消。预览只运行本地转换链，不发送上游请求。
7. **诊断设置**：自动定位默认关闭；开启后，仅今后新捕获的记录排队自动诊断。无论开关状态都保存完整系统提示词。旧记录与失败/中断任务须手动重试，避免重复收费。关闭自动定位会取消运行中与排队中的自动任务，手动任务不受影响。服务重启后任务标记中断，不自动重放。

## 旧配置自动迁移

- 迁移规则追加到已有规则之后，复用内容、边界及启停状态完全相同的现有规则；保留管理员已有规则、顺序、诊断设置与拦截记录。DSH 身份规则保留原末尾边界，不会误改 `Harnesses` 等更长名称。
- 迁移标记 `legacy_migration_version=1` 与规则写入同一加密文件，原子提交；失败会回滚并中止启动，不丢配置、不静默恢复旧替换。
- 迁移仅执行一次。管理员随后编辑、禁用、删除的规则不会因重启或旧环境变量重新出现。更新规则的 API 不能清除迁移标记。
- 迁移后原 `features.codex_compat`、`features.dsh_compat` 和对应环境变量不再控制当前请求。旧文件值保留供回滚旧版本参考；管理 API 回显这两个旧开关为关闭，并提供 `legacy_prompt_compat_migrated=true`。旧开关写入被拒绝，避免产生两套互相覆盖的配置。其他特性设置不受影响。回滚旧版本时应同时恢复迁移前的加密存储备份，不能仅更换二进制后继续使用新规则字段。
- 管理设置页将旧开关替换为新页面入口。规则列表显示“Codex 迁移”“DSH 迁移”来源，迁移规则可以正常编辑、排序、启停或删除。
- 迁移本身不会发送上游请求，不改变自动诊断开关。此前已验证的记录需要在新规则下重新验证。

## 定位与验证的判定

- 同一任务固定该记录最近一次拦截的账号及其正常请求代理，不刷新账号凭据、不轮换账号、不跨分组转移提示词、不修改账号健康状态、不递归采集诊断请求。原请求尚未释放账号槽位时最多等待 3 秒；账号不可用时返回结果不确定，可待账号恢复后手动重试。
- 先验证中性系统提示词作为对照，再验证按当前规则处理的完整系统提示词能否复现，同时保存本次定位使用的完整提示词。手动重新定位会使用最新规则，不会反复定位已经替换过的旧触发句。对照失败、模型/账号问题、限流、传输失败与不完整 SSE 都是 **结果不确定**，不能判为通过或归因于某句文本。
- 按句末标点和换行划分，保留原始字节、消息及内容块位置；以二分及补集缩减（ddmin）检查句子和组合。返回的是一个可复现的片段，可能需要多句同时存在；不保证是唯一触发点，也不代表找到了上游内部的具体审核机制。
- 请求预算默认 64 次，可设置 4–256 次，包含对照与完整复现。任务串行执行，请求间至少间隔 300ms；单请求最多 45 秒，任务最多 10 分钟；可取消。预算耗尽保留当前已复现片段，并标记未完成定位。
- “验证当前替换”最多 2 次请求：对照、经当前完整转换链处理的原始系统提示词。使用固定的 `Reply with OK.` 用户消息与最多 32 输出 token，不发送原业务对话。成功需要 HTTP 200、无错误帧、正常结束原因与 `[DONE]`。只代表该模型、所选账号、本次系统提示词检查通过，不保证包含用户对话和工具历史的业务请求一定成功。
- 开启自动诊断的保存操作与手动诊断的确认弹窗都会明确说明真实请求和用量。修改规则后不会自行发送验证请求。
- 验证期间配置版本或该记录的最新拦截时间发生变化，结果不得标为已解决。

## 存储与边界

- `prompt-guard.enc` 存在 `state_file` 所在目录（包括使用 PostgreSQL 的部署）。部署时应与现有 `data/` 卷一同持久化及备份。
- 规则、完整系统消息与诊断结果采用 AES-256-GCM 加密、随机 nonce、临时文件同步并原子替换，文件权限 0600。密钥在内存中从已有管理员 `api_key` 派生；该项为空时使用 `frontend_password`。没有管理员凭据时功能不启用。不创建新的明文密钥文件。
- **更换用于派生的管理员凭据前须保留原凭据和加密文件备份**。旧文件不能由新凭据直接解密；必须在保留原凭据的环境中完成数据迁移，或显式清理旧诊断数据后初始化。无法解密时启动失败，不静默丢弃规则与提示词。
- 默认保留 30 天、200 条，可设置 1–365 天和 1–1000 条；过期/超量淘汰最旧的非活动记录。运行/排队任务受保护；全部受保护且容量不足时明确报告捕获失败。
- 加密前总状态上限 64 MiB，单规则匹配/替换各最多 1 MiB，最多 256 条（为原有满额规则的迁移预留容量）；转换输出总文本上限 128 MiB，避免规则倍增耗尽内存。超限不截断提示词，显示存储错误或拒绝改写请求。详情可手动删除旧记录。
- 管理 API 只接受管理员密钥或控制台登录会话，分组密钥不可访问；返回 `Cache-Control: no-store`。列表和登录摘要不含完整提示词。提示词仅在详情打开时读取，页面不写入 Web Storage。

## 管理 API

所有路径以 `/admin/prompt-guard/` 为前缀。

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| GET | `summary` | 待处理数、活动数、存储错误，不含提示词 |
| GET | `config` | 规则和诊断设置、配置版本 |
| PUT | `config` | 提交完整规则列表与设置，须携带当前 `revision`；过期版本拒绝 |
| GET | `cases` | 按最近拦截排序的记录元数据，不含完整内容 |
| GET | `cases/{id}` | 完整原始/出站提示词、定位与任务结果 |
| DELETE | `cases/{id}` | 删除非活动记录 |
| POST | `cases/{id}/preview` | 当前全部转换后的完整系统消息，仅本地处理 |
| POST | `cases/{id}/locate` | 启动二分及组合定位，触发真实上游请求 |
| POST | `cases/{id}/verify` | 验证当前替换后的完整系统提示词，触发真实上游请求 |
| POST | `cases/{id}/cancel` | 取消运行或排队的任务 |
